## 1. 한 줄 요약

**Interface-First**로 코어(모델·시리즈·좌표 변환)를 렌더링과 분리하고, QML(Scene Graph) / Widget(QPainter)이 같은 계약을 소비하는 **초기 단계(0.1.0)의 고성능 Qt 차트 라이브러리**이다. 설계 문서·규율·테스트 밀도는 나이 대비 매우 성숙하지만, 프론트엔드 기능 범위와 성능 최적화는 아직 Phase 1 수준이다.

- QML은 `QQuickItem` + 내부 `QLineSeries` **composition** (다중 상속 회피, issue #57)

## 3. 레이어별 평가

### 3.1 Core — 가장 단단한 부분

**강점**

- `QAbstractSeriesModel`: insert/remove/dataChanged/boundsChanged/modelChanged로 증분 업데이트 설계가 분명함
- `QRingBufferSeriesModel`: 실시간 스트리밍용 O(1) append, `ThreadSafety` enum, batch API
- `QCoordinateTransform` + `QScaleEngine` (Heckbert nice labels) + log scale
- `QAbstractSeries`: 유효성 검증(lineWidth, dashPattern, opacity)이 **한곳**에만 존재 → QML/Widget이 동일 거절 규칙 공유 (AI.md §3.1·§3.2)
- `enum class SeriesType`로 타입 디스패치 — 매직 넘버 금지 준수

**약점 / 부채**

- `SeriesType`에 Area/Bar/Pie가 있으나 구현 없음 (의도적 예약)
- 코어만으로는 “차트”가 완성되지 않음 — 프론트엔드 의존도가 큼

### 3.2 QML Frontend — 기능적으로 앞섬

**강점**

- Scene Graph 기반 `QmlLineSeries` / `QmlScatterSeries` (60fps 스트리밍 데모와 맞춤)
- `ChartView.qml`: 축 라벨·타이틀·줌/팬/러버밴드/리셋이 QML 핸들러로 구현
- `QmlLegend`: 시리즈 추가/제거 추적, item 생명주기 관리

**약점**

- `QmlLegend.position`은 저장·시그널만 하고 레이아웃 미연동 (#93)
- Legend 토글: QML은 opacity, 테스트는 `visible == false` 기대 가능 (#94)
- 줌 상태(`_saved*`)가 QML private property — C++ API로 올리면 Widget과 더 대칭
- `QmlLineSeries`가 `QQuickItem::opacity`를 시리즈 stroke alpha로 **shadow** — 문서화되어 있으나 함정 가능

### 3.3 Widget Frontend — Phase 1 진입

**강점**

- `WidgetChartView`: 그리드·축·라인·러버밴드·휠/팬, `setXRange`/`zoom*Enabled`가 QML과 API 패리티
- `connectRepaintModel`: modelChanged 시 재배선, 제거 시 정리 — 연결 수명 관리가 신중함
- 데모: sine wave + 테마

**약점**

- **Scatter 미렌더** — QML만 scatter 있음 → AI.md §3.1 패리티 미완성
- `WidgetLineSeries`: 사실상 static `paintSeries` 래퍼 (#92)
- 매 paint 전체 포인트 → `QPolygonF` (#90)
- 축 라벨 고정 박스 → 작은 마진에서 클리핑 (#91)
- QPainter 경로라 대량 포인트에서 SG 대비 불리 (설계상 예상 범위)

### 3.4 테스트 · CI · 프로세스

**강점**

- 테스트 파일이 두꺼움: RingBuffer, StaticModel, AbstractSeries, Theme, Coordinate, ScaleEngine, QmlChartView, WidgetChartView, QmlLegend…
- 3 OS × Qt 6.7+, clang-format, cppcheck, Codecov
- `AI.md`가 매우 구체적: 패리티, 회귀 테스트, 브랜치 단일 관심사, “Solid > fast”
- Effective C++ / 명명 / 라이선스 규칙이 코드 주석과 일치하는 편

**약점**

- `TestQmlAxis`는 거의 스모크 수준
- 일부 테스트는 “크래시 없음” 위주
- README Status 문구가 실제보다 뒤처짐 (“next steps: abstract series…” — 이미 구현됨)

## 4. 설계 품질 하이라이트

| 패턴 | 적용 예 |
|------|---------|
| Interface-First | 모델·시리즈에 paint 없음 |
| Single source of truth | 시리즈 프로퍼티 검증은 코어만 |
| Composition over diamond | QmlLineSeries → 내부 QLineSeries |
| Span API | `points(first,last)` → 복사 없이 렌더 |
| Qt ownership | parent/child, QPointer로 dangling 방어 |
| 패리티 강제 | 줌 API·autoScale·테마 공유 |

코드 스타일은 전반적으로 **방어적·문서화 과다 쪽**이다. 주석이 이슈 번호·AI.md 조항을 직접 인용해, AI 협업 프로젝트로서의 추적성은 우수하다.

## 6. 리스크 · 긴장점

1. **패리티 부채**  
   AI.md는 양쪽 동시 수정을 강제하지만, Widget scatter·Area 등은 아직 없음. 규칙을 지키려면 기능 추가 속도가 느려지거나, 예외를 명시해야 함.

2. **관심사 혼합 PR**  
   #89처럼 zoom + render + (과거) legend가 한 PR에 묶이면 리뷰 비용이 큼. AI.md §3.5와 충돌 소지.

3. **QML vs C++ 상호작용 이중 구현**  
   줌/팬이 QML Handler vs Widget event로 각각 구현 → 미세 동작 차이(팬 누적 vs press 기준) 가능.

4. **성능 경로**  
   QML SG는 스트리밍에 맞춰져 있고, Widget은 전량 polyline. “고성능” 브랜딩은 현재 **링버퍼 + QML 경로**에 주로 해당.

5. **문서 drift**  
   README Status·Features가 코드보다 보수적/부정확 → 신규 기여자 혼란.
